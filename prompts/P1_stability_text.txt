СЕССИЯ 1 ИЗ 4. СТАБИЛИЗАЦИЯ, ТЕКСТ, ГЛАВНЫЙ ПОТОК.

Это задание на одну сессию AI Studio. Выполняй задачи по порядку, после каждой — сборка.
Ничего не переписывай «заодно». Если упёрся в жёсткое ограничение среды — остановись,
напиши BLOCKED, точную ошибку и что осталось.

КОНТЕКСТ
Android-проект Supertonic Reader: локальный TTS Supertonic 3 (4 ONNX-модели через
onnxruntime-android, 44.1 кГц mono PCM16, 31 язык + "na", голоса F1/F2/M1/M2), Compose M3,
один модуль app, одна MainActivity, сервис воспроизведения, импорт TXT/EPUB/PDF, экспорт,
«Аудиотека». В коде есть подтверждённые дефекты: PCM пишется на диск (session_spool,
PcmDiskCache), ошибка синтеза подменяется тишиной, engine.load и сегментация идут на главном
потоке, детектор языка запускается по всему тексту при каждом изменении, книга рендерится
одним Text, размер модели в UI неверный, загрузка ломается на HTTP 416, WakeLock истекает
через 10 минут, аудиофокус сам возобновляет речь. Всё это исправляется здесь.

ПРАВИЛА СЕССИИ
1. Один шаг = одна тема. Не более ~15 файлов за шаг; если больше — разбей шаг.
2. Не меняй версии AGP/Kotlin/Compose/ORT. Не добавляй NDK, второй модуль, вторую Activity.
3. Не добавляй сеть для синтеза/языка/аналитики, Firebase, рекламу, БД Room.
4. Не оставляй заглушек, «имитации PCM», таймеров вместо работы.
5. Не задавай уточняющих вопросов: принимай консервативное решение и фиксируй его в state.
6. В конце — обновлённый AI_STUDIO_STATE.md и отчёт по форме из последнего раздела.

ЗАДАЧИ

1) Приватность и зависимости
Удали из app/build.gradle.kts и gradle/libs.versions.toml неиспользуемое: firebase-ai и
appcheck (оба), retrofit, converter-moshi, moshi + moshi-kotlin-codegen, room
(runtime/ktx/compiler), logging-interceptor, плагин ksp (если он нужен только им), плагин
google-services (если после удаления Firebase не используется). Оставь compose, lifecycle,
activity-compose, core-ktx, coroutines, okhttp, onnxruntime-android, androidx.media.
Проверь сборку. В metadata.json убери объявление серверных возможностей (если поле не
управляется средой; если управляется — не трогай и отметь).

2) Промежуточное аудио — только RAM
Удали класс PcmDiskCache и все вызовы. Удали запись session_spool_*.pcm и временных
batch_export_*.pcm. Никакой PCM/WAV/M4A не пишется на диск, кроме конечного сохранённого
файла. Одноразово при старте удаляй остатки старых версий в cacheDir по маскам
session_spool_*.pcm и batch_export_*.pcm. Проверка: `grep -R "session_spool\|pcm_cache\|batch_export\|FileOutputStream" app/src` не должен находить запись аудио на диск.

3) Ошибка синтеза не маскируется
Если synthesizeChunk вернул null или бросил исключение: статус ERROR, сообщение с номером
фразы, чанк не считается готовым, синтез останавливается, в UI — кнопка «Повторить».
Никакой подстановки тишины вместо текста.

4) Питание, фокус, уведомления
- WakeLock: держать всё время воспроизведения/подготовки, отпускать в pause/stop/завершении/
  onDestroy. Таймаут 10 минут убрать.
- Аудиофокус: на AUDIOFOCUS_GAIN НЕ вызывать resume(); пауза по потере фокуса; учитывать
  результат requestAudioFocus.
- MediaPlayer «Аудиотеки»: AudioAttributes(USAGE_MEDIA, CONTENT_TYPE_SPEECH), запрос фокуса,
  пауза книги при старте трека.
- Уведомление и MediaSession обновлять не чаще 1 раза в секунду и только при смене текста.

5) Загрузка модели и честные размеры
- Перед загрузкой HEAD-запросы: получить Content-Length, сумму показывать в UI (ожидаемо
  ≈398 МБ) вместо «235 МБ» (два места в ModelSetupScreen).
- Range: ответ 200 → качать с нуля; ответ 416 → удалить .part и качать с нуля (сейчас тело
  416 дописывается в файл и портит его).
- После завершения файла сверить длину с Content-Length.
- checkInstalledState не должен считать файл валидным по «length > 100»: критерий — размеры
  из манифеста; статус «файл повреждён, скачать заново» при расхождении.
- Список голосов в UI должен совпадать с фактически загруженными файлами; выбранный голос
  не подменяется молча (если не загружен — сообщение, не тихий fallback).

6) Честные подписи CPU (только текст и числа)
В DiagnosticScreen и настройках: раздел «Привязка ядер CPU (Core Affinity)» переименовать в
«Потоки инференса»; убрать «Big A76 / Little A55» и любые утверждения о привязке; показывать
фактическое engine.currentThreads. Чекбоксы ядер на этом шаге не удаляй, но подпиши честно:
«влияет на число потоков; привязка к ядрам в этой сборке не реализована».

7) Текст книги — на диск, не в StateFlow
Создай data/DocumentStore.kt: импорт сохраняет полный текст в filesDir/documents/<id>.txt и
метаданные в <id>.json (title, sourceUri, charCount, chapters: [title, charStart, charEnd],
createdAt). Запись атомарная: temp + rename. В памяти — только текущая глава/абзацы.
MainViewModel больше не хранит всю книгу в StateFlow<String>. Импорт выполняется целиком в
Dispatchers.IO с прогрессом; парсеры на этом шаге не улучшай (это сессия 3), только сохраняй
результат в DocumentStore.

8) ReaderScreen без «одного Text на книгу»
- LazyColumn по абзацам; абзацы строятся один раз при открытии документа (split по "\n\n"
  с сохранением смещений).
- Подсветка только текущего абзаца (SpanStyle на абзаце).
- Автоскролл к текущему абзацу при его смене (LazyListState.animateScrollToItem).
- Счётчик символов/слов считается один раз при загрузке документа, не в композиции.
- Основной экран книги — read-only. Отдельный экран «Текст» для ручной вставки/правки с
  лимитом 50 000 символов и предупреждением при превышении; сохранение — в DocumentStore.

9) Главный поток
- engine.load(...) и сегментация — только в Dispatchers.Default, статус PREPARING в UI,
  кнопка Play не блокирует интерфейс.
- Детектор языка для подписи UI — по образцу ≤4000 символов, в Dispatchers.Default, дебаунс
  300 мс; вызов на весь текст при каждом изменении убрать.
- Сегментация чанка/главы — в фоне, не в композиции.

10) Сегментация: один проход, точные смещения
Перепиши core/TextSegmenter.kt (сохрани класс TextChunk: index, text, startOffset, endOffset,
resolvedLang):
- один проход по тексту, без indexOf на каждый чанк;
- границы предложений [.!?…] + пробел/конец; пропуск сокращений (т.е., т.к., г., д., руб.,
  Dr., Mr., etc., e.g., i.e., Ph.D. и т.п.) и одиночных инициалов; числа с точкой (15.5) не
  разрезать;
- длинные предложения (>250) резать по , ; :, затем по словам; жёсткий лимит 250;
- чанки короче 25 символов склеивать с соседним;
- первый чанк сессии ≤80 символов;
- startOffset/endOffset — точные границы непустого текста, сумма непересекающихся диапазонов
  покрывает исходник;
- resolvedLang заполняется переданным языком (политика — сессия 3).
JVM-тесты: аббревиатуры, «15.5», инициалы, длинное предложение без запятых, повторяющаяся
фраза, ё/й, 200 тыс. символов < 300 мс, точность смещений.

11) Позиция чтения
data/SessionStore.kt: JSON (documentId, chapterIndex, chunkIndex, sampleOffset, voice, steps,
speed, lang). Автосейв каждые 5 с и в onPause; восстановление при старте без автозапуска
воспроизведения.
