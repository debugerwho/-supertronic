ЭТАП 6. ЭКСПОРТ: ТРИ ФАЗЫ, КОНТЕЙНЕР В RAM, ЗАПИСЬ ТОЛЬКО В КОНЦЕ.

ЦЕЛЬ: «Создать файл» работает независимо от прослушивания, не пишет временные PCM на диск,
не отбирает движок у плеера и даёт компактный файл.

СДЕЛАЙ:
1) export/ExportPlan.kt: до старта оцени байты (chars → сек → PCM байты) и сравни с
   доступной памятью (ActivityManager.MemoryInfo.availMem, memoryClass). Если не влезает —
   отказ с понятным текстом и предложениями: «экспорт по главам», «.aac (ADTS)», «меньше текст».
2) ExportSession (export/ExportSession.kt):
   Фаза 1: весь текст → SynthesisScheduler(P3) → PcmStore.append. Прогресс 0..0.8.
            Ошибка синтеза → стоп, на диск ничего не записано.
   Фаза 2: PCM → MediaCodec AAC-LC mono, sample rate из конфига модели, битрейт параметром
            (32/48/64 кбит/с, по умолчанию 32) → access units + csd-0 в RAM-хранилище
            (export/RamByteStore.kt, блоки 4 МБ).
            Далее контейнер:
            а) androidx.media3:media3-muxer: Mp4Muxer.Builder(RamSeekableOutput(store)) —
               реализуй SeekableMuxerOutput (интерфейс WritableByteChannel: write, getPosition,
               getSize, setPosition, close) поверх RamByteStore; класс и Builder помечены
               @UnstableApi — добавь @OptIn(UnstableApi::class); добавь трек audio/mp4a-latm,
               пиши сэмплы, close. Если в выбранной версии интерфейс Muxer переехал в
               media3-transformer — не тяни его целиком, используй Mp4Muxer напрямую;
            б) если API/зависимость не резолвится — fallback: ADTS .aac (AacAdtsWriter) и/или
               WAV (WavHeader пишется при сохранении из RAM).
            Прогресс 0.8..0.98. Зафиксируй в state, какой вариант собран.
   Фаза 3: скопируй готовый контейнер в выбранный через SAF URI (ACTION_CREATE_DOCUMENT)
            через ContentResolver.openOutputStream; flush/close. Только здесь появляется файл.
            Ошибка записи → готовый результат остаётся в RAM для повтора (кнопка), без
            повторного TTS.
3) Отмена: освободить PcmStore/RamByteStore, закрыть encoder/muxer, ничего не оставлять
   на диске и в RAM. Кнопка «Отмена» видна всегда.
4) Экспорт не запускает воспроизведение и не требует Play. При одновременном чтении:
   задачи экспорта — P3, плеер всегда впереди; при P0 экспорт ждёт между чанками.
5) Имя файла: audio_<title>_<yyyyMMdd_HHmmss>.<m4a|aac|wav>; заголовок из документа.
6) Зависимости: только media3-muxer (не transformer/exoplayer), одна фиксированная версия.
   После успешной сборки запиши версию в state.

ПРИЁМКА:
- экспорт 30 минут текста: файл воспроизводится (в приложении и во внешнем плеере), стыки
  без щелчков, размер при 32 кбит/с ≈ 7 МБ на 30 мин (покажи фактический);
- на диске нет temp-файлов (проверка cacheDir), PCM не пишется;
- при одновременном чтении звук не рвётся (лог: длительность ожидания P0);
- отмена на фазе 1/2/3 не оставляет мусора и не ломает приложение;
- отчёт: пик RAM на фазах, время фаз, выбранный контейнер (M4A/ADTS/WAV).
