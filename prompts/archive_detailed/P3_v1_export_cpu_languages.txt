СЕССИЯ 3 ИЗ 4. ЭКСПОРТ ФАЙЛА, ПОТОКИ CPU, ЯЗЫКИ, ИМПОРТ ДОКУМЕНТОВ.

Задание на одну сессию. Три независимые темы — выполняй строго по порядку (A, B, C),
после каждой задачи сборка. Звуковой путь чтения не меняй: он уже сделан в сессии 2.

ОБЩИЕ ПРАВИЛА
1. Экспорт не запускает воспроизведение и не требует Play; использует тот же EngineHost
   (второй экземпляр модели запрещён), задачи синтеза — приоритет P3.
2. Никаких временных PCM/WAV/M4A на диске: контейнер собирается в RAM.
3. Не добавляй NDK/CMake/native. Реальная привязка к ядрам в AI Studio невозможна.
4. Не добавляй сеть для языков/синтеза/аналитики.
5. Консервативные решения фиксируй в AI_STUDIO_STATE.md, вопросов не задавай.

════ A. ЭКСПОРТ «СОЗДАТЬ ФАЙЛ» ════

A1. export/ExportPlan.kt — до старта оцени объём (символы → секунды → байты PCM) и сравни с
доступной памятью (ActivityManager.MemoryInfo.availMem, memoryClass). Не влезает — отказ с
понятным текстом и вариантами: «экспорт по главам», «.aac (ADTS)», «сократить текст».
Отказ принимается ДО старта, а не в середине.

A2. Три фазы (export/ExportSession.kt), прогресс и отмена на каждой:
Фаза 1 (0..0.80): весь текст → синтез (P3) → PcmStore из сессии 2. Ошибка синтеза → стоп,
на диск ничего не записано.
Фаза 2 (0.80..0.98): PCM → MediaCodec AAC-LC mono, sample rate из конфига модели, битрейт
параметром (32/48/64 кбит/с, по умолчанию 32) → access units + csd-0 в RAM-хранилище
(export/RamByteStore.kt, блоки 4 МБ). Контейнер:
  а) androidx.media3:media3-muxer: Mp4Muxer.Builder(RamSeekableOutput(store)); реализуй
     SeekableMuxerOutput (WritableByteChannel: write/getPosition/getSize/setPosition/close)
     поверх RamByteStore; классы @UnstableApi → @OptIn(UnstableApi::class); добавь трек
     audio/mp4a-latm, пиши сэмплы, close. Версию Media3 зафиксируй одну, только media3-muxer
     (не transformer/exoplayer). Если в версии интерфейс Muxer переехал в media3-transformer —
     используй Mp4Muxer напрямую, не тяни transformer целиком;
  б) если зависимость/API не резолвится — fallback: ADTS .aac (export/AacAdtsWriter.kt) и/или
     WAV (WavHeader пишется при сохранении из RAM). Какой вариант собран — напиши явно.
Фаза 3: копирование готового контейнера в выбранный файл через SAF
(ACTION_CREATE_DOCUMENT) и ContentResolver.openOutputStream; flush/close. Только здесь
появляется файл. Ошибка записи → результат остаётся в RAM, кнопка «Сохранить ещё раз»,
без повторного TTS.
A3. Отмена/ошибка в любой фазе: освободить PcmStore/RamByteStore, закрыть encoder/muxer,
не оставлять файлов и мусора. Кнопка «Отмена» видна всегда.
A4. Имя: audio_<title>_<yyyyMMdd_HHmmss>.<m4a|aac|wav>.
A5. Проверка кодека: AAC-энкодер есть? MediaCodecList; нет — сообщение и fallback.
A6. Отдельная кнопка «Создать файл» с собственным прогрессом/отменой; при одновременном
чтении экспорт уступает P0 и не рвёт звук.

════ B. ПОТОКИ CPU (ЧЕСТНО, БЕЗ ОБЕЩАНИЙ ПРИВЯЗКИ) ════

B1. CpuAffinityManager → ThreadPolicy: хранит число потоков (2/4/6/8/авто) и старую маску
для миграции настроек; threads = bitCount(mask), clamp 1..8. Не показывать «выбрано ядер: N»
как привязку.
B2. UI «Настройки»: «Потоки инференса» 2/4/6/8/авто. Вместо чекбоксов ядер — информационный
список CPU с максимальными частотами (`/sys/devices/system/cpu/cpu*/cpufreq/cpuinfo_max_freq`)
и пометкой «кластер по частоте» / «неизвестно». Никаких «Big A76 / Little A55».
B3. engine/ThreadPlacementProbe.kt: раз в 2 секунды во время синтеза читает
/proc/self/task/*/stat (поле 39 — последний CPU), агрегирует; в диагностике строка
«потоки синтеза выполнялись на CPU: … (наблюдение, не привязка)». Без root, ошибки чтения
игнорировать.
B4. Калибровка: кандидаты 2/4/6/8, один текст/голос/шаги, 1 прогрев + 1 замер, только через
EngineHost; сохранять threads, rtf, Build.FINGERPRINT, версию ORT, revision модели;
автоматически при старте не запускать.
B5. Смена числа потоков — только по действию пользователя (перезагрузка сессий), не на чанк.
B6. В state зафиксируй: реальная привязка к ядрам требует native/отдельного процесса и
делается вне AI Studio; в этой сборке её нет.

════ C. ЯЗЫКИ И ИМПОРТ ДОКУМЕНТОВ ════

C1. Список языков = официальные 31: en ko ja ar bg cs da de el es et fi fr hi hr hu id it lt
lv nl pl pt ro ru sk sl sv tr uk vi, плюс "na". Удали "zh" и "sr" из селектора, детектора и
любых проверок.
C2. core/LanguagePolicy.kt: resolve(chunkText, contextText, userChoice) → (code, confidence,
source). Приоритет: ручной выбор > уверенный язык чанка > контекст абзаца > ru (только если
кириллица и неоднозначно). Уверенно неподдерживаемый язык → UNSUPPORTED: сообщение и
предложение выбрать вручную, не подменять русским. Иероглифы: ja только при наличии каны,
иначе UNSUPPORTED (не zh). Проверка code перед передачей в движок; в debug — assert.
Решение по чанку кэшируется в TextChunk.resolvedLang; детекция — в фоне при планировании.
C3. Кэш синтеза (если остался RAM-кэш): ключ = text + lang + voice + steps + revision модели
+ версия нормализации/детектора. Дискового кэша аудио нет.
C4. EPUB (DocumentImporter): читать META-INF/container.xml → OPF → manifest + spine → главы
в порядке spine (не по алфавиту файлов); кодировка из XML-declaration/meta charset, поддержать
windows-1251; потоковое чтение записей, без словаря всех HTML в памяти; заголовок из
<title>/<h1..h3>, иначе «Глава N»; раскрывать HTML-сущности (&nbsp; и др.).
C5. PDF: приоритет — PDFBox-Android (`com.tom-roush:pdfbox-android`) с постраничным
извлечением и лимитом памяти; если зависимость не резолвится/не подходит — оставить текущий
экстрактор, но добавить проверку осмысленности (доля букв/пробелов, длина) и честное
сообщение «PDF без текстового слоя или с нестандартной кодировкой не поддерживается».
Не читать файл дважды (ByteArray + String).
C6. TXT: срезать BOM, определять UTF-8/UTF-16/1251, читать потоково, не держать две копии.
C7. Тесты: язык ru/en/uk/смешанный ru+en/короткое «Да»/неподдерживаемый (китайский);
EPUB-фикстура, где алфавитный порядок не совпадает с spine; PDF-фикстура с кириллицей
(текстовый слой).

ОПРЕДЕЛЕНИЕ ГОТОВНОСТИ
A. Экспорт 30 минут текста: файл воспроизводится, стыки без щелчков, размер при 32 кбит/с
≈7 МБ (покажи фактический); на диске нет temp; отмена на каждой фазе без мусора; при
одновременном чтении звук не рвётся; в отчёте пик RAM и время фаз.
B. Таблица 2/4/6/8 потоков (реальные числа или «не измерено»); grep не находит «A76/A55» и
«привязк» в UI; probe выводит наблюдаемые CPU; второго движка нет.
C. grep не находит "zh"/"sr" в списке языков; таблица «вход → ожидание → факт» по языкам;
EPUB в порядке spine; PDF либо читается на реальной кириллической книге, либо честно
ограничен; нет ANR при импорте 5 МБ.
