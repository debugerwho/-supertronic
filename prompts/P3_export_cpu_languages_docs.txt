БЛОК 0. ЗАПРЕЩЁННЫЕ РЕГРЕССИИ (проверь, что не сломал)
══════════════════════════════════════════════════════════════════
0.1 audio/AudioTrackSink.flush() обязан сбрасывать _totalWrittenFrames / headOffsetFrames /
    lastObservedHead в 0. Абсолютная позиция хранится ТОЛЬКО в PlaybackClock.baseSampleOffset.
    Если вернуть пересчёт headOffsetFrames — после каждого seek позиция уедет вперёд.
0.2 seekToChunk() флашит ровно один раз (через clock.resetToSample), не дважды.
0.3 pause() НЕ флашит sink и запоминает currentChunkWriteOffset; resume() продолжает запись
    с этого байта через startPlaybackLoop(gen, index, startByteOffset). Не переписывай чанк
    с нуля — это вернёт повтор фразы.
0.4 pause()/stop() увеличивают generationId. Отмена корутины не останавливает блокирующий
    AudioTrack.write(); цикл останавливается только по смене поколения.
0.5 Экспорт не должен возвращать List<ByteArray> или любой другой буфер на всю книгу.
    Только потоковые писатели MediaCodecExporter.AudioFileWriter (write/finish/abort).
0.6 EngineHost.rawEngine — internal, наружу не выносить. EngineHost.load() идемпотентен
    (повторный вызов с тем же каталогом и числом потоков не перезагружает модель).
0.7 core/SourceIndex: курсор при построении + бинарный поиск. Не возвращай indexOfFirst
    в цикле и полный пересчёт смещений на каждый чанк.
0.8 audio/PcmStore: maxCapacityBytes клампится 64–256 МБ, put() отказывается от чанка
    больше 4 МБ, чтение — copyInto() в переиспользуемый буфер.
0.9 engine/ModelManager.checkInstalledState(): допуск ±2 % к ожидаемому размеру (кэш HEAD
    или манифест), при расхождении с кэшем — инвалидация записи, а не «файл повреждён».
0.10 Не добавляй NDK/CMake/native, второй экземпляр модели, дисковый кэш аудио,
     Firebase/Retrofit/Room/Moshi, сеть для синтеза/языков/аналитики.

A. ЭКСПОРТ «СОЗДАТЬ ФАЙЛ» — что осталось доделать
══════════════════════════════════════════════════════════════════

A1. Сохранение через SAF, а не в личную папку.
    Сейчас файл пишется в filesDir/saved_recordings. Нужен пользовательский выбор места:
    - в UI — ActivityResultContracts.CreateDocument с MIME "audio/mp4" (.m4a), "audio/aac"
      (.aac, если включишь ADTS) или "audio/wav";
    - писать сразу в выбранный Uri: ContentResolver.openFileDescriptor(uri, "rw") →
      ParcelFileDescriptor.fileDescriptor → MediaMuxer(fd, MUXER_OUTPUT_MPEG_4)
      (конструктор с FileDescriptor есть с API 26, minSdk у нас 26). Для WAV — OutputStream
      поверх ContentResolver.openOutputStream(uri).
    - Обобщи MediaCodecExporter.M4aWriter так, чтобы он принимал либо File, либо FileDescriptor
      (два конструктора MediaMuxer), а не только путь.
    - Fallback: если fd не seekable и muxer падает — писать во внутренний файл
      filesDir/exports, затем скопировать байтами в Uri и удалить внутренний. В отчёте укажи,
      какой путь реально использован.
    - Файл в целевой папке не должен появляться до фазы сохранения: при ошибке Uri-файл
      удаляется (DocumentsContract.deleteDocument или contentResolver.delete).
    Оставь и старый путь (личная папка + «Открыть в другом плеере» через FileProvider) как
    второй вариант кнопки — аудиотека на него опирается.

A2. Битрейт из настроек, а не 128 кбит/с по умолчанию.
    openM4aWriter(destinationFile, sampleRate, bitRate) уже принимает bitRate — пробрось выбор
    пользователя 32/48/64 кбит/с (32000/48000/64000), AAC-LC, mono, 44100 Гц.
    Покажи в UI текущее значение. Для WAV битрейт не применяется (PCM 16 бит).

A3. Экспорт не должен рвать чтение.
    Единственный движок сериализует инференс через EngineHost.withEngine, поэтому экспорт
    обязан уступать воспроизведению. Реализуй в цикле экспорта перед каждым чанком:
      • признак занятости: playbackState.status == PLAYING/BUFFERING, либо в планировщике
        есть незакрытый P0 для текущего чанка (добавь в SynthesisScheduler
        fun hasPendingCurrent(index: Int): Boolean, не меняя логику очереди);
      • если занято — delay(100) и повтор, максимум 5 с ожидания, затем всё равно синтезируй
        (иначе экспорт зависнет при ошибке воспроизведения);
      • двигай прогресс экспорта только по факту записи чанка.
    Критерий: при одновременном чтении и экспорте 30 минут текста счётчик sink.getUnderruns()
    не растёт (замер до/после, числа в отчёт).

A4. Отмена и ошибки.
    Отмена на любой фазе: writer.abort() (уже удаляет частичный файл), остановка батча,
    сообщение «Экспорт отменён», во внутренней папке и в SAF не остаётся мусора.
    Ошибка синтеза на чанке N → «Ошибка синтеза чанка N», файл удалён, повторный экспорт
    начинает заново. Кнопка «Отмена» доступна всегда.

A5. Проверки до старта (без отказа по RAM — книга в памяти больше не держится).
    - свободное место на целевом томе (StatFs): оценка размера = оценка_секунд × битрейт/8 × 1.1,
      для WAV — секунд × 88200; если места меньше — отказ до старта;
    - оценка времени экспорта: символы → секунды (/13) × RTF последних чанков, показывать
      «≈ N мин», без обещаний;
    - наличие AAC-энкодера (MediaCodecList) — иначе предложить .wav.

A6. Имя файла: audio_<title>_<yyyyMMdd_HHmmss>.<m4a|aac|wav>, где title — очищенный от
    / \ : * ? " < > | и обрезанный до 40 символов; при пустом — «book».

A7. В отчёт: фактический размер файла и длительность (30 минут текста, 32 кбит/с ≈ 7 МБ —
    покажи реальное число), время фаз, пик RAM (dumpsys meminfo или Debug.MemoryInfo),
    проверка воспроизведения во внешнем плеере, отсутствие temp-файлов
    (ls filesDir/exports и cache после экспорта).

══════════════════════════════════════════════════════════════════
B. ПОТОКИ CPU — честно, без обещаний привязки
══════════════════════════════════════════════════════════════════

B1. Число потоков как самостоятельная настройка.
    Сейчас CpuAffinityManager хранит маску ядер и выводит threads = bitCount(mask).
    Переведи на явное число: 2 / 4 / 6 / 8 / авто (авто = min(8, max(2,
    availableProcessors()/2))). Храни в prefs ключ thread_count; при первом запуске
    мигрируй значение из старой маски (bitCount), затем маску игнорируй.
    Нигде в UI не писать «выбрано ядер: N» и не показывать чекбоксы ядер как привязку.

B2. Экран настроек CPU.
    Радио «Потоки инференса: 2 / 4 / 6 / 8 / авто» + фактическое значение после загрузки
    движка (EngineHost.currentThreads). Ниже — информационный список CPU: номер, максимальная
    частота из /sys/devices/system/cpu/cpu*/cpufreq/cpuinfo_max_freq (нет файла —
    «неизвестно»). Подпись: «Список информационный. Привязка потоков к конкретным ядрам
    в этой сборке не реализована».

B3. Наблюдение размещения потоков.
    engine/ThreadPlacementProbe.kt: во время синтеза раз в 2 с читает /proc/self/task/*/stat,
    берёт поле 39 (последний CPU), агрегирует «CPU: n вызовов». В диагностике строка
    «потоки синтеза выполнялись на CPU: 4 (12), 5 (9), 6 (3) — наблюдение, не привязка».
    Без root, ошибки чтения игнорировать, probe полностью выключается флагом.

B4. Калибровка (если её ещё нет в текущем виде).
    Кандидаты 2/4/6/8, один текст, один голос, steps=3, 1 прогрев + 1 замер на кандидата,
    только через EngineHost.load(numThreads) + withEngine. Сохранять: threads, синтез мс,
    длительность, RTF, Build.FINGERPRINT, версию ORT, revision модели. Автозапуска при
    старте нет, только по кнопке.
    В отчёт — таблица 2/4/6/8: реальные числа или «не измерено» (эмулятор ≠ телефон).

B5. Смена числа потоков применяется только по действию пользователя и требует перезагрузки
    движка (EngineHost.load с новым numThreads), не на чанк и не во время чтения
    (во время чтения — предупреждение «остановите чтение»).

C. ЯЗЫКИ И ИМПОРТ ДОКУМЕНТОВ
══════════════════════════════════════════════════════════════════

C1. Список языков = 31 официальных + "na":
    en ko ja ar bg cs da de el es et fi fr hi hr hu id it lt lv nl pl pt ro ru sk sl sv tr uk vi.
    В LanguageDetector и UI сейчас остались "zh" и "sr" — убери их из списков выбора и из
    пользовательских сообщений. Детекция иероглифов: если найдена кана → ja, если только
    хань (без каны) → результат UNSUPPORTED с текстом «Китайский не поддерживается моделью,
    выберите язык вручную», но код "zh" нигде не сохраняется и не показывается как язык.
    Аналогично сербская кириллица → не "sr": определи как ru/bg по эвристике или UNSUPPORTED.

C2. core/LanguagePolicy.kt (новый файл, без android.* — чтобы тестировался на JVM):
    resolve(chunkText, paragraphContext, userChoice) → (code, confidence, source, unsupportedReason?).
    Приоритет: ручной выбор пользователя > уверенный язык самого чанка > язык абзаца >
    ru только при кириллице и неоднозначности. Уверенно неподдерживаемый язык → UNSUPPORTED
    (сообщение пользователю, без молчаливой подмены русским). Проверка code перед передачей
    в движок; в debug — assert. Результат кэшируется в TextChunk.resolvedLang.
    Добавь проверку: code ∈ 31+na, иначе ошибка.

C3. Импорт EPUB — порядок spine, а не алфавит.
    DocumentParser уже ищет container.xml → content.opf. Проверь и исправь:
    - главы идут в порядке spine (idref → manifest href), а не по именам файлов;
    - кодировка из XML-декларации / meta charset, поддержка windows-1251;
    - заголовок главы из <title> или первого <h1..h3>, иначе «Глава N»;
    - раскрытие сущностей (&nbsp;, &amp;, &#1040;);
    - чтение записей потоково: не держать в памяти словарь всех HTML-файлов сразу.
    Тест-фикстура: EPUB, где алфавитный порядок файлов ≠ spine.

C4. Импорт PDF.
    Добавь проверку осмысленности извлечённого текста: доля букв и пробелов, средняя длина
    «слова», общая длина. Не прошло — честное сообщение «PDF без текстового слоя или с
    нестандартной кодировкой не поддерживается», без мусорных глав. Файл не читать дважды
    (ByteArray + String). PDFBox не добавлять, если он не резолвится — оставь текущий
    экстрактор с проверкой.

C5. Импорт TXT.
    Срезать BOM, определять UTF-8 / UTF-16LE/BE / windows-1251 по BOM и валидности
    декодирования, читать потоково, не держать две копии текста.

C6. Тесты (JVM, без Android):
    ru / en / uk / смешанный ru+en / короткое «Да» / хань без каны → UNSUPPORTED;
    LanguagePolicy: ручной выбор важнее автоопределения; абзац-контекст;
    EPUB-фикстура со spine ≠ алфавит; WAV-заголовок (уже есть — не сломай).
