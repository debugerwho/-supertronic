БЛОК 0. ЗАПРЕЩЁННЫЕ РЕГРЕССИИ
══════════════════════════════════════════════════════════════════
0.1 audio/AudioTrackSink.flush() сбрасывает счётчики кадров в 0; абсолютная позиция —
    только в PlaybackClock.baseSampleOffset. Иначе seek «уезжает» на всю сессию вперёд.
0.2 pause() не флашит sink, запоминает байтовый offset; resume() продолжает с него
    (startPlaybackLoop(gen, index, startByteOffset)). Повтор фразы после паузы — регресс.
0.3 pause()/stop() увеличивают generationId (только это останавливает цикл записи).
0.4 Экспорт потоковый: MediaCodecExporter.openM4aWriter/openWavWriter, без List<ByteArray>.
0.5 EngineHost.rawEngine — internal; load() идемпотентен; второй экземпляр модели запрещён.
0.6 SourceIndex — курсор + бинарный поиск; PcmStore — кламп 64–256 МБ и copyInto();
    ModelManager — допуск ±2 % и инвалидация кэша HEAD.
0.7 Нет NDK/CMake, нет дискового кэша аудио, нет Firebase/Retrofit/Room/Moshi.

══════════════════════════════════════════════════════════════════
1. ОВЕРЛЕЙ («плавающая панель»)
══════════════════════════════════════════════════════════════════
Один владелец окна — playback/OverlayController.kt (вынеси из FloatingOverlayManager всю
работу с WindowManager). Требования:
- show/hide идемпотентны; повторный show не создаёт второе окно, hide без show — no-op;
- при stop()/onDestroy()/смене главы view удаляется гарантированно, без WindowLeaked;
- 20 циклов start/stop подряд (лог + `adb shell dumpsys window windows | grep -i leak`)
  без исключений и без висящих окон;
- состав: Play/Pause, −10 с, +10 с, Стоп, текущий абзац (2 строки), «Открыть приложение»;
- кнопки −10/+10 вызывают тот же seekToSeconds(), что и в приложении (не отдельную логику);
- разрешение SYSTEM_ALERT_WINDOW запрашивается только по действию пользователя; при отказе
  в настройках остаётся кнопка «Разрешить», приложение не падает и чтение работает.

══════════════════════════════════════════════════════════════════
`./gradlew :app:testDebugUnitTest` должен быть зелёным. Обязательный минимум:

  ResumePolicy загрузки модели: Range 206 / 200 / 416 / неполный файл;
  SessionStore: сохранение/восстановление JSON.

6. ФИНАЛЬНАЯ ПРОВЕРКА ПО ИНВАРИАНТАМ
══════════════════════════════════════════════════════════════════
Ничего не меняй, пока не отчитаешься. По каждому пункту: ВЫПОЛНЕНО / НЕ ВЫПОЛНЕНО /
НЕ ПРОВЕРЕНО + файл:строка.
 1. Нет ONNX/сегментации/детекции на Dispatchers.Main.
 2. Нет записи промежуточного аудио на диск (только конечный файл при сохранении).
 3. Ровно один экземпляр движка (EngineHost); OrtSession создаются только внутри него.
 4. Все OrtSession.Result/OnnxTensor закрыты (включая цикл шагов и textEncResult).
 5. Ошибка синтеза → ERROR с номером фразы, не тишина и не пропуск.
 6. PCM не в Java-куче; usedBytes ≤ maxCapacityBytes всегда.
 7. Ползунок не вызывает seek на каждый кадр.
 8. Нет выдуманных размеров/языков/метрик; языки 31 + na.
 9. Нет двух параллельных синтезов; экспорт уступает P0 и не рвёт звук.
10. core/ и language/ не зависят от android.*; JVM-тесты проходят.
11. ViewModel не вызывает engine напрямую.
12. Позиция/документ/настройки сохраняются и восстанавливаются.
13. MediaSession отдаёт позицию и скорость; уведомление ≤ 1 раза в секунду.
14. WakeLock держится во время чтения и отпускается во всех путях.
15. Аудиофокус: нет автовозобновления на GAIN; библиотека уважает фокус.
16. Оверлей: один владелец, нет утечек при stop.
17. Нет Firebase/Retrofit/Room/Moshi; Media3 одной версии (если добавлен).
18. Отчёт не содержит утверждений о производительности телефона без замера.
19. После seek позиция точная: baseSampleOffset == sampleStart целевого чанка,
    а не «плюс всё записанное ранее».
20. Пауза 5 минут → resume: фраза не повторяется и не теряется (байтовый offset).
21. Экспорт не держит книгу в RAM: пиковый RSS на 30-минутном экспорте < 800 МБ.
22. Нет аллокации ByteArray на каждый чанк в цикле записи (переиспользуемый буфер).
23. Языковой код, уходящий в движок, всегда из списка 31+na.
