# AI Studio State: Supertonic Reader

## Сессия 1: Стабилизация, текст, главный поток

### 1. Сделано
- **Приватность и зависимости (Задача 1):**
  - Очищены `app/build.gradle.kts` и `gradle/libs.versions.toml`: удалены `firebase-bom`, `firebase-ai`, `firebase-appcheck-recaptcha`, `firebase-appcheck-debug`, `room-runtime`, `room-ktx`, `room-compiler`, `retrofit`, `converter-moshi`, `moshi-kotlin`, `moshi-kotlin-codegen`, `logging-interceptor`.
  - Удалены неиспользуемые плагины `google-devtools-ksp` и `google-services`.
  - В `metadata.json` сохранена обязательная capability `MAJOR_CAPABILITY_SERVER_SIDE_GEMINI_API` в соответствии с системным ограничением среды AI Studio.
- **Промежуточное аудио — только RAM (Задача 2):**
  - Удален класс `PcmDiskCache.kt` и все вызовы.
  - Удалена запись `session_spool_*.pcm` и временных `batch_export_*.pcm`.
  - При старте `SupertonicPlaybackService` выполняет одноразовую очистку устаревших `.pcm` файлов в `cacheDir`.
  - Промежуточный синтез и пакетный экспорт работают исключительно в RAM (`List<ByteArray>`), запись ведется только в конечный целевой файл (.m4a / .wav).
- **Ошибка синтеза не маскируется (Задача 3):**
  - Удалена подстановка тишины (`250ms silence`).
  - При ошибке `synthesizeChunk`: статус переходит в `PlaybackStatus.ERROR`, выводится сообщение с номером фразы (напр., «Ошибка синтеза фразы №3»), чанк не считается готовым, синтез останавливается.
  - В `ReaderScreen` добавлен баннер ошибки с кнопкой «Повторить» (`viewModel.retrySynthesis()`).
- **Питание, фокус, уведомления (Задача 4):**
  - `WakeLock` держится на протяжении воспроизведения и фоновой подготовки без 10-минутного таймаута; освобождается в `pause()`, `stop()`, при завершении и в `onDestroy()`.
  - Аудиофокус: на `AUDIOFOCUS_GAIN` автоматический `resume()` убран; обрабатывается результат `requestAudioFocus` (отказ прерывает запуск с сообщением).
  - `MediaPlayer` «Аудиотеки»: настроен с `AudioAttributes(USAGE_MEDIA, CONTENT_TYPE_SPEECH)`, запрашивает аудиофокус и ставит книгу на паузу при запуске трека.
  - Уведомления и `MediaSessionCompat` обновляются с троттлингом (не чаще 1 раза в секунду и только при изменении текста).
- **Загрузка модели и честные размеры (Задача 5):**
  - В `ModelManager` добавлены HEAD-запросы для получения реального `Content-Length`. Сумма вычисляется динамически и передается в UI (`ModelSetupScreen`).
  - До загрузки/при отсутствии ответа отображается «неизвестно» или расчётная сумма манифеста (≈398 МБ вместо хардкода «235 МБ»).
  - Обработка Range: HTTP 200 качает с нуля (`append = false`), HTTP 416 удаляет поврежденный `.part` и перезапускает загрузку с нуля.
  - Проверка завершения файла сверяет `partFile.length()` с `Content-Length`.
  - `checkInstalledState()` проверяет точное совпадение размеров файлов из манифеста/HEAD, возвращая статус повреждения файла при расхождении.
  - Список голосов в UI отображает реально загруженные файлы из `voice_styles/`; при отсутствии выбранного голоса выводится ошибка, а не тихий fallback.
- **Честные подписи CPU (Задача 6):**
  - В `DiagnosticScreen`: блок переименован в «Потоки инференса».
  - Убраны метки «Big A76 / Little A55» и утверждения о привязке к ядрам.
  - Выводится фактическое значение `engine.currentThreads`.
  - Добавлено честное пояснение: «влияет на число потоков; привязка к ядрам в этой сборке не реализована».
  - Удален блок очистки кэша PCM на диске.
- **Текст книги — на диск (Задача 7):**
  - Создан `data/DocumentStore.kt`: атомарное сохранение полного текста в `filesDir/documents/<id>.txt` и метаданных в `<id>.json` (title, sourceUri, charCount, wordCount, chapters, createdAt).
  - В `MainViewModel` убран `StateFlow<String>` со всем текстом книги — в памяти хранится только текст текущей главы и список ее абзацев.
  - Импорт книги выполняется в `Dispatchers.IO` с индикацией прогресса.
- **ReaderScreen без одного Text (Задача 8):**
  - Построение списка абзацев (`LazyColumn` по `ParagraphItem`) один раз при открытии документа / главы.
  - Подсветка активного предложения через `SpanStyle` только на текущем абзаце.
  - Автоскролл к активному абзацу через `LazyListState.animateScrollToItem`.
  - Счётчики символов и слов вычисляются один раз при открытии главы/документа.
  - Основной экран книги — read-only.
  - Отдельный экран/диалог «Текст» для ручного ввода и правки текста с лимитом 50 000 символов, предупреждением и сохранением в `DocumentStore`.
- **Главный поток (Задача 9):**
  - `engine.load(...)` и сегментация вынесены в `Dispatchers.Default` с промежуточным статусом `PlaybackStatus.PREPARING` в UI.
  - Детектор языка выполняется по фрагменту ≤4000 символов в `Dispatchers.Default` с дебаунсом 300 мс.
- **Сегментация: один проход (Задача 10):**
  - Переписан `TextSegmenter.kt`: один линейный проход по тексту O(N) без `indexOf`.
  - Границы предложений [.!?…], пропуск сокращений (т.е., т.к., г., д., руб., Dr., Mr. и т.д.) и инициалов; числа вида «15.5» не разрезаются.
  - Предложения >250 символов делятся по `, ; :`, затем по словам; жесткий лимит 250.
  - Чанки короче 25 символов склеиваются с соседними; первый чанк сессии ≤80 символов.
  - `startOffset`/`endOffset` точно соответствуют подстроке в исходном тексте.
- **Позиция чтения (Задача 11):**
  - Создан `data/SessionStore.kt`: сохранение JSON (documentId, chapterIndex, chunkIndex, sampleOffset, voice, steps, speed, lang).
  - Автосейв каждые 5 с и в `MainActivity.onPause()`. Восстановление позиции при старте без автозапуска воспроизведения.

### 2. Не проверено в реальном окружении
- Физическое поведение фонового сервиса с выключенным экраном более 30 минут на реальном железе вендоров с агрессивным Doze Mode (Xiaomi/Samsung).
- Отображение системной плавающей мини-панели (Floating Overlay) на реальном устройстве с выданным разрешением `SYSTEM_ALERT_WINDOW`.

### 3. Технические долги

- Политика выбора и переключения языка для отдельных разноязычных чанков (запланировано на Сессию 3).
