# Supertonic Reader — мастер-инструкция для Google AI Studio (Gemini 3.8 Flash)

Дата: 22.10.2026. Ветка: `arena/c3e0cbd7-supertronic` (коммит `a97c17b` + аудит `AUDIT_2026-10-22.md`).
Основание: переписка с Codex, файлы `AGREED_RAM_ONLY_ARCHITECTURE_RU.md` (приоритет),
`AUDIOBOOK_STAGED_REQUESTS.md`, `CURRENT_CHECKPOINT_CHANGE_OPTIONS_RU.md`,
`AI_STUDIO_PLAN_CORRECTIONS.txt`, `AI_STUDIO_POST_BUILD_AUDIT_PROMPT.txt`,
`GOOGLE_AI_STUDIO_PROMPT.txt`, плюс независимый аудит текущего кода.

Документ состоит из двух частей:

1. **Что должно быть построено** — архитектура, контракты, бюджеты, инварианты, этапы с приёмкой.
2. **Как этим пользоваться** — `prompts/00…12`: готовые сообщения для AI Studio, по одному на этап.

---

## 0. Как пользоваться (коротко)

1. Откройте проект в AI Studio Build (Android). Перед любым этапом сделайте **checkpoint**.
2. Вставьте `prompts/00_session_bootstrap.txt` — это «паспорт» проекта для модели.
3. Далее по одному этапу: `01 → 02 → … → 09`, после каждого — приёмка из §15.
4. После каждого этапа требуйте обновлённый `AI_STUDIO_STATE.md` и **ZIP-экспорт**.
5. Не переходите к следующему этапу, пока не выполнены критерии приёмки текущего.
6. Если модель начала переписывать проект целиком — откат к checkpoint и повтор с явным
   ограничением «меняй только файлы X, Y».

Этапы 0–6 обязательны. Этап 7 (AAC-архив RAM) — по результатам замеров. Этапы 8–9 — качество и гигиена.

## 1. Ключевые архитектурные решения (и почему именно так)

Ниже — решения, которые модель **не должна пересматривать по своему усмотрению**. Если она
считает решение неверным, она обязана остановиться и написать аргументы, а не менять молча.

### D1. Промежуточное аудио — только RAM, без диска
По `AGREED_RAM_ONLY_ARCHITECTURE_RU.md`: никаких `session_spool*.pcm`, дискового LRU,
`batch_export*.pcm`, mmap-аудиофайлов, гигабайтных `.part`. Диск — только для: весов модели,
текста книги, `SharedPreferences`/JSON-состояния и **явно сохранённого конечного** аудиофайла.
Следствие: `PcmDiskCache` удаляется полностью (сейчас он пишет PCM на флэш и удаляет старое —
это ровно тот цикл износа, которого просили избежать).

### D2. Хранилище PCM — off-heap (`DirectByteBuffer`), блоками
Лимит Java-кучи на Android — 256–512 МБ, поэтому книга в `ByteArray`/`MutableMap<Int, ByteArray>`
физически не помещается (текущий код падает на ~30–40 мин аудио). PCM живёт в пуле
`DirectByteBuffer` по 4 МБ. Бюджет задаётся в байтах и проверяется до записи.
Арифметика: PCM16 mono 44,1 кГц = **88 200 Б/с = 5,29 МБ/мин = 317 МБ/час**.

### D3. Один владелец движка + приоритетный планировщик
`EngineHost` — единственный, кто вызывает ONNX-сессии (`Mutex`, `StateFlow<EngineState>`).
Все задачи синтеза проходят через `SynthesisScheduler` с приоритетами:

| Приоритет | Задача | Правило |
|---|---|---|
| P0 | чанк, который нужен плееру сейчас | всегда первым |
| P1 | цель перемотки | сразу после P0 |
| P2 | опережение (lookahead) до целевого буфера | только если буфер ниже цели |
| P3 | экспорт | только если P0–P2 пусты |
| P4 | «плановая длительность» (DP) для оценки таймлайна | по остаточному времени |

Один рабочий поток синтеза (сам ONNX внутри может использовать N потоков). Экспорт **не может**
отобрать движок у воспроизведения — сейчас именно это ломает звук (общий `@Synchronized`).

### D4. Единица синтеза — предложение; первые чанки короткие
Чанк = одно предложение (120–200 символов, максимум 250); очень короткие («Да.») склеиваются
с соседним. **Первый чанк сессии ≤ 80 символов**, чтобы первый звук появился за один короткий
инференс. Это не «размер буфера» и не «размер хранения» — три разные величины.

### D5. Таймлайн — по готовому аудио, в сэмплах
Позиция и длина считаются в source-сэмплах, а не в «фразах» и не в «±15/3». Ползунок
ограничен **готовым** диапазоном; для ещё не озвученного текста есть переход по абзацу/фразе
(это отдельное действие, а не перетаскивание). Оценка полной длительности (`≈ 2:14:30`)
появляется по мере DP-предсказаний и всегда помечена как оценка. Это вариант 7А из
`AGREED_RAM_ONLY_ARCHITECTURE_RU.md`: будущий звук не считается доступным таймлайном.

### D6. Два независимых задания, один движок
«Читать с подготовкой вперёд» и «Создать файл» — отдельные кнопки, прогресс, пауза, отмена.
Оба используют один тёплый экземпляр модели. Экспорт удерживает свой PCM до конца конвертации;
режим чтения может вытеснять PCM в сжатый архив (этап 7). Политики не смешиваются.

### D7. Экспорт — три фазы, контейнер собирается в RAM
1) весь текст → PCM-блоки в RAM; 2) PCM → AAC access units → M4A **в RAM**; 3) завершённый M4A →
запись в выбранный файл (SAF). Для (2) используется `androidx.media3:media3-muxer`:
`Mp4Muxer.Builder(SeekableMuxerOutput)` + собственная реализация `SeekableMuxerOutput` поверх
RAM-хранилища (интерфейс публичный, `@UnstableApi`). Системный `MediaMuxer` в RAM не умеет.
Fallback, если зависимость/API недоступны: WAV в RAM (заголовок пишется при сохранении) и/или
ADTS-AAC (`.aac`, без контейнера). Модель обязана сообщить, какой вариант реально собрался.

### D8. AAC-архив RAM — отдельный этап с воротами
Нужен, чтобы «готовить далеко вперёд» не стоило гигабайт: вне окна прослушивания PCM
кодируется в AAC-LC mono 44,1 кГц (32 или 48 кбит/с, по умолчанию 32) и живёт в RAM как
access units + codec config + индекс. Окно: **45 с позади и до 20 мин впереди** (по бюджету).
32 кбит/с = 4 КБ/с = 14,4 МБ/час, вся книга 3:20 ≈ 48 МБ. Перекодирование AAC→PCM→AAC при
перемотках запрещено: каждый диапазон кодируется один раз, декодированный PCM — вытесняемый кэш.
Включать только после этапа 6 и только если замеры покажут, что окна не хватает.

### D9. CPU: в AI Studio — потоки и наблюдение, привязка — вне AI Studio
`AGREED` требует «реальное ручное закрепление потоков через небольшой native helper». **В AI Studio
это невозможно**: среда не поддерживает NDK/CMake/собственный native-код, а ORT 1.19.2 на
Android не даёт thread affinity через `SessionOptions`. Поэтому:

* **в AI Studio**: маска ядер превращается в число intra-op потоков; UI честно называется
  «Потоки инференса»; добавлен `ThreadPlacementProbe`, который читает
  `/proc/self/task/<tid>/stat` (поле 39) и показывает, на каких CPU реально выполнялись потоки;
  подписи «Big A76 / Little A55» убираются, кластеры определяются по `cpufreq`/`cpu_capacity`
  с честным «неизвестно»;
* **вне AI Studio** (handoff, `prompts/12`): либо отдельный процесс `:engine` с
  `sched_setaffinity` на старте (единственный проверяемый способ, т.к. ORT создаёт свои потоки),
  либо собственный native-пул. Критерий приёмки — `Cpus_allowed_list` в `/proc/<pid>/task/*/status`.

Это осознанное отклонение от `AGREED`, вызванное средой. Обещать «галочки ядер» в AI Studio нельзя.

### D10. Языки: 31 + `na`, решение по чанку
Официальный набор: `en ko ja ar bg cs da de el es et fi fr hi hr hu id it lt lv nl pl pt ro ru
sk sl sv tr uk vi` + `na`. Китайского и сербского в модели **нет** — убрать из списка и из
детектора. Язык определяется по чанку (короткое/неоднозначное — по контексту абзаца, затем
приоритет ru), результат кэшируется в чанке. Уверенно неподдерживаемый язык → честное сообщение
и выбор пользователя, а не принудительный русский.

### D11. Состояние — JSON на диске, без Room
Room подключён, но БД в проекте нет. Хранение: `documents/<id>.txt` (текст книги),
`documents/<id>.json` (метаданные, главы), `session.json` (документ, позиция, настройки).
Атомарная запись: временный файл + rename. Автосохранение позиции каждые 5 с и в `onPause`.

### D12. UI: ленивый список, отдельная панель плеера, две кнопки
Книга рендерится `LazyColumn` по абзацам (не одним `Text` на миллион символов). Панель плеера —
фиксированная, вне прокрутки. Кнопки «Читать» и «Создать файл» — раздельные, с независимым
прогрессом. Редактор — отдельный экран с ограничением (50 тыс. символов) и предупреждением.

### D13. Приватность: убрать лишние зависимости
В APK сейчас `firebase-ai`, `appcheck`, `retrofit`, `moshi`, `room`, `logging-interceptor`, при
тексте «100% офлайн, нулевая телеметрия». Удалить неиспользуемое, оставить OkHttp (загрузка
весов), `org.json` (парсинг). `metadata.json` не должен объявлять серверные возможности.

### D14. Целостность модели
Никаких выдуманных размеров: реальные `Content-Length` через HEAD, сверка суммы, проверка
открытия сессий. SHA-256 — по значениям, которые вы получите с HF; до этого — статус
«хэш не задан» в диагностике, а не тихая галочка. Официальный объём ONNX ≈ 398 МБ (404 МБ со
всеми ассетами), а не 235 МБ.

### D15. Тестируемость
`SpeechEngine`, `AudioSink`, `Clock`, `PcmStore` — интерфейсы. Логику (сегментация, политика
языка, бюджеты, планировщик, экспортный план, ADTS/WAV-заголовки, resume-политика загрузки)
покрывать обычными JVM-тестами с фейками; Robolectric — только там, где нужен Android.

## 2. Правила работы в AI Studio с Gemini 3.8 Flash

Модель: 1M токенов контекста, 64k вывода, уровни «thinking» low/medium/high (по умолчанию
medium), сильна в длинных инженерных задачах, но склонна к «большим переписываниям» и к
оптимистичным отчётам. Отсюда — жёсткий протокол.

### 2.1. Уровни мышления
* `high` — этапы 2, 3, 6, 7, 8 (архитектура, память, экспорт, AAC).
* `medium` — этапы 1, 4, 5 (реализация).
* `low` — косметика, тексты, иконки.

### 2.2. Формат каждого шага (требовать явно)
```
1. План: 3–7 пунктов, какие файлы затронуты (только существующие пути + новые).
2. Изменения: по файлам, полными блоками функций, а не «...».
3. Сборка: команда + результат (успех/ошибка + текст).
4. Тесты: какие добавлены, что показали.
5. Проверено / НЕ проверено (обязательный раздел).
6. Обновлён AI_STUDIO_STATE.md.
```
Запрещено: «должно работать», «предположительно», отчёт о замерах, которых не было,
«производительность улучшена» без чисел.

### 2.3. Ограничители, которые надо повторять в каждом этапе
* Не менять версии AGP/Kotlin/Compose/ORT без отдельного обоснования и проверки сборки.
* Не добавлять NDK/CMake/Rust/KMP, второй модуль, вторую Activity.
* Не добавлять сетевые вызовы для синтеза/языка/аналитики.
* Не писать аудио на диск, кроме конечного файла.
* Не выполнять инференс/сегментацию/детекцию на главном потоке.
* Не создавать второй экземпляр движка.
* Не заменять реальную функциональность заглушкой, таймером или тишиной.
* Не более ~8 файлов и одна тема на один шаг; иначе — разбить и спросить.

### 2.4. Управление контекстом
Контекст 1M позволяет держать весь проект (~6 тыс. строк ≈ 80–100 тыс. токенов), но не
переписку целиком. Поэтому:
* в начале сессии — `00_session_bootstrap.txt` + `AI_STUDIO_STATE.md` + текущий этап;
* вместо длинных объяснений — ссылки на файлы и этот документ;
* при «поехавшем» контексте — новый чат, bootstrap + state + один этап;
* после этапа — ZIP-экспорт, чтобы был откат вне AI Studio.

## 4. Контракты (что должно быть в коде)

```kotlin
// engine
interface SpeechEngine {
    val state: StateFlow<EngineState>          // NotLoaded, Loading, Ready(threads), Failed(reason)
    suspend fun load(modelDir: File, threads: Int): Result<Unit>
    suspend fun synthesize(req: SynthesisRequest): SynthesisResult
    fun close()
}
data class SynthesisRequest(
    val text: String,            // уже нормализованный чанк
    val lang: String,            // из LanguagePolicy, проверенный по списку модели
    val voiceId: String,
    val steps: Int,              // 2, 5, 10
    val speed: Float = 1.0f      // ВСЕГДА 1.0 в этой версии; параметр реально применяется
)
data class SynthesisResult(
    val pcm: ByteArray, val sampleRate: Int, val durationSec: Double,
    val synthMs: Long, val rtf: Double
)

// аудио
interface AudioSink {
    fun play(); fun pause(); fun flush(); fun release()
    fun write(bytes: ByteArray, offsetBytes: Int, lengthBytes: Int): Int
    var speed: Float
    fun bufferedSourceSeconds(): Double     // делить на speed для wall-clock
    fun positionSamples(): Long             // с учётом flush
}

interface PcmStore {
    fun append(key: ChunkKey, pcm: ByteArray): Boolean   // false = бюджет исчерпан
    fun read(key: ChunkKey): ByteArray?                  // для отдачи в sink
    fun evictOutside(windowStartSample: Long, windowEndSample: Long)
    fun usedBytes(): Long
    fun clear()
}

class SynthesisScheduler(engine: EngineHost, store: PcmStore, clock: PlaybackClock) {
    fun submit(task: SynthesisTask, priority: Priority, generation: Int)
    fun cancelBelow(priority: Priority)
    fun pauseAll() / resumeAll()
}
```

Требования к реализации:
* все `suspend`-вызовы движка — на `Dispatchers.Default` (`engine/` не имеет права на `Main`);
* отмена — через `Job.cancel()` **и** проверку `generation` перед записью в `PcmStore`;
* `write` в `AudioTrack` — слайсами ≤100 мс, с проверкой отмены между слайсами;
* ни один `Result`/`OnnxTensor` не остаётся незакрытым (включая `textEncResult`);
* шум латентов — `ThreadLocalRandom.nextGaussian()`, а не ручной Box–Muller на чанк.

## 5. Память: конкретные числа и правила

| Величина | Значение | Комментарий |
|---|---|---|
| PCM16 mono 44,1 кГц | 88 200 Б/с; 5,29 МБ/мин; 317 МБ/час | базовый расчёт |
| Бюджет PCM в режиме чтения | **128 МБ** (≈ 24 мин) | настройка 64/128/256 МБ |
| Окно позади playhead | 45 с | для мгновенной перемотки назад |
| Опережение (по умолчанию) | 10 мин (настройка 5/10/20) | ограничено бюджетом |
| AAC 32 кбит/с | 4 КБ/с; 14,4 МБ/час | для этапа 7 |
| Вся книга 3:20 AAC32 | ≈ 48 МБ | payload без контейнера |
| Экспорт 3:20, PCM в RAM | 1,06 ГБ | off-heap, обязательна проверка бюджета |
| Экспорт 3:20, M4A 32 кбит/с | ≈ 48 МБ | в RAM + запись в файл |

Правила:
* решение «влезет/не влезет» принимает `ExportPlan` **до** старта: если оценка > 40 % доступной
  памяти процесса (`ActivityManager.MemoryInfo.availMem` и `memoryClass`), предложить экспорт по
  главам или AAC-поток (этап 7) вместо отказа «на середине»;
* аллокация блока 4 МБ; при `OutOfMemoryError`/`null` — деградация с сообщением, не краш;
* в диагностике всегда показывать: `PcmStore.used/max`, число чанков, `RTF` последнего чанка,
  underruns, потоки и наблюдаемое размещение по CPU.

## 6. Сегментация и смещения (исправить до всего остального)

Текущий `TextSegmenter` использует `fullText.indexOf(sentence, searchOffset)` на каждый чанк
(O(n²) на книге) и теряет точность на повторяющихся фразах. Нужен один проход:

1. нормализовать переводы строк (`\r\n → \n`), не менять длину текста (или хранить карту
   смещений, если меняете);
2. идти по тексту, отслеживая конец предложения (`[.!?…]` + пробел/конец), пропуская
   сокращения (`т.е.`, `г.`, `д.`, `Dr.` и т.д.) и одиночные инициалы;
3. резать длинные предложения по `, ; :` (не по словам, если можно), при отсутствии — по словам
   с жёстким лимитом 250;
4. для каждого чанка сохранять **точные** `charStart/charEnd` (без `trim` внутри диапазона:
   диапазон = границы непустого текста);
5. склеивать чанки короче 25 символов с соседним;
6. первый чанк сессии — до 80 символов;
7. `resolvedLang` заполняется `LanguagePolicy`, а не «defaultLang, если не auto».

Тесты (JVM): аббревиатуры, числа с точкой (`15.5`), инициалы, длинное предложение без запятых,
повторяющаяся фраза, текст с `ё`/`й`, emoji, 200 тыс. символов (проверка времени < 300 мс и
суммы длин чанков = длине исходника без пробелов на стыках).

## 7. Таймлайн, перемотка, «что слушаю» vs «что готовлю»

* `SourceIndex` строит для каждого чанка `[startSample, endSample)` по фактическим длительностям
  синтеза; до синтеза — оценка DP (только для отображения «≈»).
* `ReadyMap` хранит готовые диапазоны (могут быть фрагментированы после перемотки вперёд).
* Ползунок: диапазон `0..readyEnd`; при drag — фиксируется отображаемый диапазон и двигается
  только UI; по `onValueChangeFinished` — один целевой seek (никаких десятков перезапусков).
* Seek внутри готового: старт с точного байтового смещения внутри чанка; `AudioTrack.flush()`,
  `PlaybackClock` сбрасывает `framesSinceFlush`.
* Seek в неготовое: P1-задача, состояние `BUFFERING`, старый звук не продолжает играть;
  по готовности — воспроизведение с целевого сэмпла.
* Кнопка «−10 с / +10 с» — арифметика по сэмплам, не по индексам чанков.
* Pause: останавливает и воспроизведение, **и** синтез (кроме уже начатого чанка), освобождает
  WakeLock. «Подготовка вперёд» продолжается только если пользователь явно её включил.
* Смена аудиофокуса/уход в другое приложение: пауза + сохранение позиции; **автовозобновления
  по `AUDIOFOCUS_GAIN` нет** — только по действию пользователя.

## 8. Плеер и сервис (исправить текущие дефекты)

| Дефект сейчас | Требование |
|---|---|
| WakeLock на 10 мин без продления | держать всё время чтения/подготовки, отпускать в pause/stop/complete |
| Авторезюм на `AUDIOFOCUS_GAIN` | не возобновлять; корректно обрабатывать отказ в фокусе |
| Library `MediaPlayer` без атрибутов и фокуса | `AudioAttributes(USAGE_MEDIA, CONTENT_TYPE_SPEECH)` + фокус, пауза книги при старте |
| Уведомление/MediaSession на каждую фразу | throttle ≤1/с; в MediaSession передавать позицию в мс и `speed`, поддержать `onSeekTo` |
| `startService()` из `init` ViewModel | запуск сервиса только по действию пользователя, `startForeground` сразу |
| Нет сохранения позиции | автосейв каждые 5 с, восстановление при старте |
| `START_NOT_STICKY` при убийстве процесса | состояние восстановимо из `SessionStore`, чтение начинается по кнопке |

## 9. Экспорт: точный алгоритм

```
ExportSession.start(document, voice, steps, format, bitrate):
  plan = ExportPlan.estimate(chars, format, bitrate)
  if (!plan.fitsMemory) → сообщить причину и предложить варианты (главами / .aac / короче)
  Phase 1: for chunk in chunks: engine.synthesize → PcmStore.append (off-heap)
           прогресс 0..0.8; при ошибке — стоп, ничего не записано на диск
  Phase 2: encoder = MediaCodec AAC-LC mono 44.1k, bitrate
           for block in PcmStore: feed encoder → access units + csd-0 → RamByteStore
           mux = Mp4Muxer.Builder(RamSeekableOutput(store)).build()
           mux.addTrack(Format.Builder().setSampleMimeType("audio/mp4a-latm")...); write samples; close
           прогресс 0.8..0.98
  Phase 3: ContentResolver.openOutputStream(uri) → copy(store) → flush/close
           только теперь появляется файл; при ошибке — готовый M4A остаётся в RAM для повтора
  cleanup: PcmStore.clear() только после успешной фазы 3 (или по явному отказу пользователя)
```

Обязательно:
* битрейт — параметр (32/48/64 кбит/с), по умолчанию 32; текущие 128 кбит/с неверны по задаче;
* `MediaCodecInfo` проверка: есть ли AAC-энкодер; если нет — WAV/ADTS fallback с сообщением;
* никаких временных файлов; при отмене — освободить RAM, не оставлять мусор;
* имена: `audio_<title>_<yyyyMMdd_HHmmss>.<ext>`, заголовок из документа;
* экспорт не запускает воспроизведение и не требует Play.

## 10. Загрузка модели и целостность

1. `HEAD` на каждый файл → `Content-Length`; сумма отображается в UI (≈398 МБ), а не «235 МБ».
2. Скачивание `.part`, `Range`; ответ `200` на Range-запрос → начать заново; `416` → **удалить
   `.part` и качать с нуля** (сейчас тело 416 дописывается в файл и портит его).
3. После файла: `length == Content-Length`; при наличии — SHA-256; иначе статус «хэш не задан».
4. `checkInstalledState()` не должен считать файл валидным по `length > 100`; критерий — размеры
   из манифеста + успешное открытие ONNX-сессий (проверка при первом запуске, результат кэшировать
   с версией).
5. Ошибки — человеческим языком: «нет места», «сеть», «файл повреждён, скачать заново».
6. Голоса: 4 выбранных (`F1,F2,M1,M2`) — ок, но список в UI должен совпадать с загруженным
   и не подменять выбранный голос молча.

## 11. Языковая политика

```
resolve(chunkText, contextText, userChoice) -> LangResolution(code, confidence, source)
  userChoice != AUTO → код пользователя (приоритет выше всего)
  иначе: детектор по чанку; если уверенность низкая → контекст абзаца;
         если всё ещё неоднозначно → ru (только если кириллица);
         если уверенно определён неподдерживаемый язык → UNSUPPORTED (сообщение + ручной выбор)
  проверка: code ∈ официальных 31 ∪ {"na"}; иначе ошибка разработчика (assert в debug)
```
Детектор для UI (подпись «Авто · RU») работает по образцу ≤4 тыс. символов в фоне, не по всему
тексту при каждом нажатии клавиши. Результат по чанку кэшируется в `TextChunk.resolvedLang`.

## 12. CPU/потоки: что именно сделать в AI Studio

1. UI: «Потоки инференса» — 2 / 4 / 6 / 8, значение по умолчанию из калибровки или 4.
2. `EngineHost.load(threads)` перезагружает сессии только по явному действию (не на каждый чанк).
3. `ThreadPlacementProbe`: раз в 2 с читает `/proc/self/task/<tid>/stat`, поле 39 (`processor`),
   агрегирует по потокам ONNX (по TID, зафиксированным при старте синтеза — грубо, через
   `Runtime` нельзя; допустимо показывать «в процессе синтеза потоки выполнялись на CPU: 6,7»).
4. Кластеры: `cpufreq/cpuinfo_max_freq` по каждому CPU; если недоступно — «неизвестно».
5. Калибровка: кандидаты 2/4/6/8, один и тот же текст/голос/шаги, по 2 прогона, результат в
   таблицу; сохранять с `Build.FINGERPRINT` + версия ORT + revision модели; не запускать
   автоматически при старте.
6. Запрещено: писать «Big A76/Little A55» без проверки; обещать привязку; менять число потоков
   на каждом чанке.

Вне AI Studio (`prompts/12`): отдельный процесс `:engine` + `sched_setaffinity` на старте,
проверка `Cpus_allowed_list`; только после доказанной пользы по замерам.

## 16. Риски и как их ловить

| Риск | Признак | Действие |
|---|---|---|
| Модель переписывает проект | десятки файлов в диффе | откат, повтор с «меняй только X» |
| «Улучшила» аудио-путь заодно | изменились `dp/speed`, fade, steps | откат этапа, сравнение WAV |
| OOM на книге | `OutOfMemoryError`, рост RSS | проверить, что PCM не в куче; бюджет |
| Сборка ломается после добавления Media3 | конфликт версий Compose/Kotlin | зафиксировать одну версию Media3, не тянуть transformer/exoplayer |
| Media3 muxer API недоступен | `Unresolved reference: Mp4Muxer` | fallback WAV/ADTS, зафиксировать факт, не выдумывать |
| PDF «работает» на тестовом файле | пустой текст на реальной книге | тест на реальной кириллической книге до приёмки |
| Эмулятор AI Studio принят за Poco | «плавно/быстро» в отчёте | запрет на выводы о производительности из эмулятора |
| Оверлей течёт | `WindowLeaked`, `isShowing` после stop | `OverlayController` с одним владельцем, тест stop→start×20 |
